成都理工大学工程技术学院 ACM 集训队 QQ 群机器人：老师发布比赛链接 → 抓取、提取、超管确认后存档；按群控制资料可见与通知范围；征集登记自动统计；主动提醒默认开启，公共来源自动抓取可选。

技术栈：Python 3.10+ / 双接入协议（OneBot-NapCat 或个人 QQ ｜ QQ 开放平台官方机器人） / SQLite / OpenAI 兼容大模型 API / APScheduler。

> 接入协议由 `ACM_BOT_PROTOCOL` 切换：`onebot`（默认，功能完整，需偶尔扫码）或 `qqbot`（官方机器人，稳定不扫码，主动消息受平台配额限制）。业务逻辑完全一致。

## 功能总览

| 功能 | 行为 | 状态 |
|------|------|------|
| 比赛发布 | 提取存档、超管确认、修正版本与按群通知 | 已实现，真实 QQ 待验收 |
| 主动提醒 | 开赛持久计划、报名/征集/课程多节点、重试与去重 | 离线验证通过，默认开启 |
| 问答 | 本群 FAQ 与结构化资料；未答问题收集；可选模型消歧 | 默认本地检索，寒暄零 token |
| 征集登记 | 幂等报名、修改/取消、名额校验、公开数字汇总、本机私有导出 | 已实现 |
| 来源监控 | 条件请求、正文变化检测、超管处理待审更新 | 默认关闭，不自动广播 |

### 数据模型

- **公共比赛（competitions）**：已确认的公共对象；`competition_notify_groups` 控制可见/通知群范围，未指定时面向允许群。新发布默认限定来源群；不依赖模型提示词隔离。
- **学校安排（org_events）**：学校统一安排，`shareable=1` 的公开项所有群可看。
- **群内安排（training_sessions / group_faq / unanswered_questions / collections）**：全部带 `group_id`，严格按群隔离。
- **征集登记（collection_responses）**：同一征集+成员幂等登记，取消保留历史；容量、截止、字段校验与写入同事务。
- **提醒投递（reminder_deliveries）**：去重键含群、对象、类型、目标时间及节点，自动迁移旧键；成功回执单独持久化，失败有界重试，关闭/改期取消，过期不发。
- **来源抓取（competition_sources）**：记录 ETag/Last-Modified/正文哈希/最近抓取时间/状态/错误，支撑低频抓取与变化检测。

发布比赛时，正式比赛、来源 URL 和已抓取正文的哈希在同一事务保存。开启 `ACM_AUTO_FETCH_ENABLED=1` 后，新发布链接按 `ACM_FETCH_MIN_INTERVAL_MINUTES` 进入后台监控；正文未变化不再调用模型，有变化则保存待审更新。`/抓取状态` 可查看来源登记与最近检查结果。

超管 `/修正` 官网地址时，比赛字段与有效监控来源在同一事务切换；旧来源停用并保留历史。新地址尚未抓取时只建立空基线任务，首次监控抓取才保存真实正文哈希；`重新提取` 成功则同时保存实际抓取地址及正文基线，抓取或提取失败保留原资料和来源。

后台更新使用 `/待审列表`、`/待审批准 <更新id>`、`/待审拒绝 <更新id> [原因]` 处理，仅超管可执行。批准合并已提取的有效字段，未包含或为空的字段保留当前值；首次发布默认先私聊超管确认。这三条命令只回复发起群，列表只列比赛及改动字段名，不发送提取正文、操作者或拒绝原因；需要清空可选字段时用 `/修正 字段=` 显式操作。

## 自动开赛提醒与通知自检

- **官方群授权由群主操作**：群主需在目标群的机器人管理页开启“机器人主动在群聊内发言”。普通成员资料卡中的“接收机器人推送”开启，不能代替群级主动发言授权。实际部署已验证：群主授权后，状态从 `allow_proactive_msg=false` 变为 `true`，独立主动测试消息真实送达。
- 老师发布 → 超管同意后，比赛、来源群范围、未来开赛提醒计划在同一数据库事务保存；无需再手工设定时器。
- 开启发布确认却未配置超管时，会在抓取/模型调用前提示补齐审核人；只有显式关闭确认流程才直接发布。读取通知范围失败的比赛跳过本轮提醒，其他对象继续投递。
- 默认开赛前 **30 分钟、15 分钟**各一次，使用北京时间。专用任务每30秒检查持久化队列；不能承诺秒级精确或终端必达。
- 审批时已经过去的节点不创建；改期时取消旧计划并创建新时间的未来节点；时间未定不排计划。停机恢复时只发送仍在120秒宽限内的节点，超过标记 expired，避免补刷过时消息。
- `/提醒状态 [页码]` 可提前查看本群未来7天的比赛、报名截止、征集及课程提醒，显示名称、具体节点时间和投递状态，每页10项。比赛开赛节点标为待发送或未排队；扫描式提醒标为待扫描，查看不创建队列、不发送消息、不调用模型。平台权限暂停、失败/过期与统计仍可查看；关闭主动消息时暂停投递、不消耗重试次数，过期节点不会追发。
- 超管可用 `/通知测试 群 <群标识>` 或 `/通知测试 私聊 [用户标识]` 主动发送一条测试消息，再在当前会话收到含错误码的结果。群内省略参数默认测本群，私聊省略参数默认测自己；测试会真实发一条消息，不自动触发。
- 官方 QQ 返回 `40034105` 时，按群持久暂停主动通知，`/提醒状态` 显示权限拒绝和恢复步骤；跳过投递不增加尝试次数，其他群和当前消息的被动回复照常处理。修复平台权限后，由超管在目标群发送 `@机器人 /通知测试 群`；主动接口成功返回消息 ID 才解除暂停。恢复后仅投递仍有效的节点，已过期或重试耗尽的记录不会补发。
- 官方群测试可在末尾选择格式：`@机器人 /通知测试 群 Markdown` 或 `@机器人 /通知测试 群 文本`；私聊测试群时先补目标群标识，例如 `/通知测试 群 <群OpenID> Markdown`。每次只发送一条指定格式的主动测试消息。成功回执后，在同一事务保存本群格式并解除暂停，后续发布与提醒沿用，重启后保留；失败或缺少消息 ID 不改原格式。不指定格式时沿用本群已验证格式，尚未测试的群默认文本；`/提醒状态` 可查看。
- 官方群测试还会尝试读取目标群的 `bot_state.allow_proactive_msg`，显示平台记录的实际开关。该接口有白名单限制：无法读取、缺字段或返回类型不符均显示“暂未核实”，不能解释为开关关闭，也不会抹掉真实发送结果。一次读取最多等待5秒，不在定时任务中轮询；整个测试和提醒不调用 LLM。

比赛报名截止、征集截止和课程开课统一使用 `ACM_REMIND_OFFSET_HOURS`（默认 `24,1`），每个节点单独去重；课程的每周实例也分别记录。开赛前提醒使用独立分钟节点，倒计时按实际发送时间计算；即使自定义的节点很短，开赛后也不补发。全部提醒使用本地自然文案，**0 次模型调用、0 token**。升级前已经发送的无节点旧记录继续阻止重发，新活动使用完整多节点。

仅配置旧 `ACM_REMIND_BEFORE_HOURS`、未配置多节点的部署继续使用旧值；自动补齐 `.env` 不会擅自加入 `24,1`。希望切换多节点时请显式添加 `ACM_REMIND_OFFSET_HOURS`。节点必须是有限正数，非法值在启动时拒绝。周赛预生成会覆盖配置中最早的提醒窗口；其他周期扫描提醒使用很短或相近节点时，也应调小 `ACM_REMIND_CHECK_INTERVAL_MINUTES`。

### 主动额度节流：聚合晨报 + 被动搭便车

官方 QQ 协议每群每天只有 1~4 条主动消息额度，因此提醒升级为「定时聚合 + 被动尾随」双轨：

- **聚合晨报**：每天 `ACM_DAILY_DIGEST_TIME`（默认 `08:30`）为每个授权群生成一条事务总览，汇总今日课程、48 小时内截止的征集、24 小时内开赛且预检就绪的比赛，只占 1 条主动额度。三类都为空的群直接跳过，不发空消息；正文为纯文本，不含 Markdown 语法。
- **只承诺能推的比赛**：晨报里的比赛必须通过 `/比赛状态` 同款预检（群白名单、接入能力位、主动总开关、群熔断、比赛-群绑定、未来待发节点），查得到但到点不会推的比赛不会写进晨报。
- **被动搭便车**：群员触发只读查询（`/课程列表`、`/FAQ列表`、`/帮助`、`/比赛状态`、`/群状态`、`/提醒状态` 等）时，被动回复尾部追加一条最紧急待办——12 小时内截止的报名（附 `/报名 <id>` 快捷命令）或 2 小时内开赛的比赛。单群 10 分钟冷却，零消耗主动额度；写操作与出错/无权限的回复不搭车。
- **单群失败不阻塞**：晨报逐个群推送，某群遇到主动消息配额耗尽（`11253`/`11263`）按群熔断跳过并记告警，次日自动恢复尝试，也可使用 /通知测试 验证；其余群继续，单群生成或发送异常也只影响该群。

发布、修正、超管确认、定时提醒、直接回复共用统一通知入口。应用错误包括 `[validation]`、`[permission]`、`[internal]`、`[fetch]`、`[llm]`；投递错误包括 `[not_connected]`、`[disabled]`、`[target_not_allowed]`、`[authentication]`、`[forbidden]`、`[active_forbidden]`、`[rate_limited]`、`[timeout_unknown]` 等。未知平台错误保留为 `[unknown]`，不会猜测成“额度用完”。网络超时存在平台已收但本地未确认的可能，重试不能保证严格 exactly-once。

### 双协议保持可切换

`ACM_BOT_PROTOCOL=onebot` 使用 NapCat/OneBot；`qqbot` 使用 QQ 开放平台 botpy。配置协议后需重启，不会同时登录两个接入。两套身份标识不同：OneBot填QQ号/群号，官方填对应 openid，不能直接复用QQ号。

官方群同时兼容 `GROUP_AT_MESSAGE_CREATE` 与 `GROUP_MESSAGE_CREATE`。后者可能包含未 @ 机器人的群聊，只有平台 `mentions.is_you=true` 才标记喊话；默认普通群聊不回复、不调用模型。同一群内同一消息的新旧事件去重处理。botpy 缺少全量事件解析器时，本项目在登录后、网关连接前为当前连接补齐，保留原始 `mentions`；已原生支持时不覆盖，也不修改已安装的 SDK 文件。解析入口对照 [官方 ConnectionState](https://github.com/tencent-connect/botpy/blob/master/botpy/connection.py) 与 [网关分发](https://github.com/tencent-connect/botpy/blob/master/botpy/gateway.py)，全量消息的 @ 判断对照 [AstrBot 官方 QQ 适配](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/platform/sources/qqofficial/qqofficial_platform_adapter.py)。

新群启用：先在目标群发送 `@机器人 /帮助`。未授权时，机器人会给出包含本群真实标识的 `/加群 ...`，由超管复制到私聊执行，再回群发送 `@机器人 你好`。官方群不能使用 QQ 客户端显示的群号授权；`/加群` 会拒绝常见的短数字群号。以前误加的数字记录可用 `/删群 原群号` 删除，不会自动改动既有白名单。若仍出现 `_parser unknown event group_message_create`，应更新本项目并重启服务；仅加白名单不能修复 SDK 的解析缺失。

已配置的超管也可在目标群发送 `@机器人 /认领此群 <QQ群号> <群备注名>`，同时登记真实群号并授权当前群；私聊 `/选群` 和 `/群配置` 支持使用已登记的群号。官方协议下超管配置仍须填写平台的成员 openid。

官方被动回复只关联当前入站消息的 `msg_id`，同一消息的多条回复递增 `msg_seq`；定时和跨群通知不借用历史消息ID，不把被动发送失败悄悄改成主动重发。官方主动消息仍受平台权限、频控和配额限制，创建计划不等于平台允许投递。实际可用性请用通知测试确认。参见 [官方消息收发文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)。

遇到 `40034105` 时先验证通道，再决定是否更换接入方式：

- 已核对用户提供的 [acmerQQ-group-bot 赛前提醒](https://github.com/td1336065617/acmerQQ-group-bot/blob/master/src/scheduler.py) 与 [通知入口](https://github.com/td1336065617/acmerQQ-group-bot/blob/master/main.py)：截图中的洛谷赛前15分钟文案确实来自该实现，支持官方 QQ。它通过 AstrBot 的 `context.send_message` 进入官方适配器；[适配器源码](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/platform/sources/qqofficial/qqofficial_platform_adapter.py) 默认使用原生 Markdown，群主动发送不带 `msg_id`，并生成独立 `msg_seq`。本项目已补充可选原生 Markdown、独立主动消息序号与成功格式记忆，用实际发送结果验证差异，不能把旧讨论中的平台限制泛化为“官方机器人都无法群主动发送”。
- [官方群消息接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html) 将 `40034105` 定义为主动消息权限拒绝，`40034100` 才是主动消息频控。APScheduler 的 `Job executed successfully` 只表示任务函数正常返回，不能代替平台成功回执或群内收信。
- [NoneBot QQ 适配器](https://github.com/nonebot/adapter-qq/blob/master/nonebot/adapters/qq/bot.py) 和 [官方 botpy](https://github.com/tencent-connect/botpy/blob/master/botpy/api.py) 同样调用 `POST /v2/groups/{group_openid}/messages`，主动消息不依赖 `msg_id`。本项目沿用这一路径；换 SDK 预计不能解决服务端权限拒绝。botpy 的部分异常只保留中文消息，本项目兼容识别该形状并保留受控错误码。
- [AstrBot 的同类实测讨论](https://github.com/AstrBotDevs/AstrBot/issues/10454) 也报告群主动消息返回 `40034105`。`is_wakeup` 属于单聊召回能力，当前群发送接口没有这个字段，不作为群定时提醒的替代方案。旧版文档与当前文档存在差异，以现行接口和目标机器人的真实回执为准。
- 腾讯官方插件的 [同类问题讨论](https://github.com/tencent-connect/openclaw-qqbot/issues/43) 曾有平台限制的维护者回复，也有找不到配置入口的用户反馈。这些历史案例不能证明当前所有应用都不可用。应先完成目标群、发送格式、独立序号和实际群开关的对照测试；仍被拒绝时，再通过官方文档页底的开发者社区，提供应用信息、请求时间和 `trace_id` 请平台核查，不凭空假定后台必有自助开通入口。不要公开 AppSecret 或 access_token。
- 群里开启“允许主动发送”后，先执行主动测试；返回“平台已接受”且群内收到独立测试消息，再用未来的比赛验证定时投递。如果仍是 `40034105`，应继续核实平台权限，或评估已有的 NapCat/OneBot 接入。后者使用登录中的普通 QQ 账号，需要维护登录和重连；提醒、FAQ 与审批逻辑可沿用，但白名单及既有按群数据需要显式映射，不能直接把 OpenID 当 QQ 号使用。当前不会自动切换协议。

## 消息指令

| 场景 | 示例 | 权限 | 行为 |
|------|------|------|------|
| 发布比赛 | `@机器人 发布 https://example.com/contest` 或 `@机器人 发布 比赛名称及说明` | 老师/超管 | 有链接时抓取，抓取失败则按原文提取；无链接也可提交，默认私聊超管确认 |
| 待确认申请 | `/待确认列表` | 老师看自己，超管看全部 | 查看等待超管确认的发布申请 |
| 白名单管理 | `/加群 12345`、`/加老师 10001`、`/群列表`、`/老师列表` | 超管管理；老师/超管可查看列表 | 动态授权群与老师，**立即生效无需重启**；查看现有授权 |
| 身份认领（官方协议） | `/认领此群 123456789 集训队群`、`/认领老师 10001 李老师` | 群内触发；认领群限超管，认领老师限超管或已授权老师 | 官方协议只给哈希 openid，认领后把 openid 与真实群号/QQ号对上号，提示里显示「名字 (群号)」，并同步放行白名单/老师名单 |
| 通知范围 | `/通知群 5 111,222` | 超管 | 限定某场比赛只通知指定群；`全部` 恢复全局 |
| 修正比赛 | `/修正 3 official_time=2026-12-01 19:00` | 超管 | 纠正已发布比赛字段并通知各群 |
| 来源待审更新 | `/待审列表`、`/待审批准 3`、`/待审拒绝 3 原因` | 超管 | 处理后台来源更新；部分字段合并，回复仅发起群 |

超管私聊可以按群名或完整标识查看配置，不再只返回“收到（OpenID）”：

```text
/群配置                     # 列出可选群
/群配置 集训队              # 本群周赛开关、负责老师、近期比赛和未来提醒
/群配置 全部                # 各群摘要
/群提醒 集训队              # 指定群的完整提醒预览，可在末尾加页码
/周赛设置 集训队 开启       # 仅启用这个群的周赛；关闭会取消该群未来节点
/群老师 集训队 老师标识     # 多个老师用逗号隔开；“清空”移除负责关系
```

也可直接问“这周集训队的群有什么比赛，有哪些老师”。匹配已授权群的标识、名称或授权备注，不调用模型；重名时要求选择。没有名称时先用 `/命名群 群标识 集训队`，老师可用 `/命名人 老师标识 李老师` 命名。按群查询只在超管私聊中跨群展示；群内查询不展示其他群的配置。

周赛开关按群持久保存，并覆盖该群在 `ACM_WEEKLY_CONTEST_GROUPS` 中的基线，其他群不变；未明确启用的群不会看到或收到自动周赛。星期、时间和名称沿用全局模板；`/通知群` 仍用于普通比赛，对自动周赛只显示范围并引导使用周赛开关，避免两种设置互相覆盖。`ACM_WEEKLY_CONTEST_ENABLED=0` 只关闭自动生成，已有比赛和提醒不会因此删除，停用某群周赛请用该群的关闭命令。

负责老师是人工登记的负责关系，不把全局老师名单或 QQ 群成员当成该群负责老师。只能绑定已授权的老师，再次设置会替换本群完整负责名单，未登记时明确显示未登记；登记不授予或缩小既有管理权限。新开关和负责关系在业务清理脚本中作为必要配置保留。

QQ 官方后台「高级设置 → 菜单与指令」添加快捷入口：

1. 群内使用的命令选「群聊场景」，点击「添加指令」。
2. 触发方式选「发送指令」；「指令」填写本项目已经支持的完整命令文字，包括 `/`，例如 `/帮助`。「打开页面」用于跳转 HTTPS 网页，不会执行机器人命令。
3. 「功能说明」填写简短介绍，仅用于显示。公开查询可关闭「仅管理员可见」；开启后仅对 QQ 群管理员展示入口，和本项目的超管/老师白名单不同，不会授予机器人管理权限。
4. 保存后，回到指令列表打开该项右侧开关；灰色表示尚未启用。
5. 在对应群里 @机器人或输入 `/` 选择指令测试；需要参数时，在聊天输入框补全后发送。

后台新增名字不会自动注册代码命令，发送的文字必须与本项目支持的命令一致。私聊管理入口选择「好友场景」，本项目现有私聊管理仍只对超管开放。此次只精简帮助与提供配置说明，没有按示例 `/competition` 新增功能或代改 QQ 后台设置。参见 [QQ 官方菜单与指令文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/menu-panel/)。

管理查询、征集等操作使用斜杠命令，比赛发布也支持下面的自然说法。

发布也支持 `@机器人 添加一个比赛今天上午10点15分开始`、`添加一场比赛，2026年11月7号上午10点15，ACM算法比赛开始`。这些明确请求直接提交真实待确认申请，不由问答模型回答“记下了”。简单的名称加时间在本地解析，0 次模型调用；今天、明天、后天、星期等以北京时间为准，未写日期的钟点按今天处理并在确认单说明。未提供名称时暂名“临时比赛”，确认单会提示管理员核对。老师/超管发送带明确钟点的比赛开始陈述，也可走自然语言发布路径；普通成员仍无发布权限。复杂公告继续调用提取器，提取时提供当前北京时间作为相对日期参照。

提交后群回执会显示真实申请编号、解析后的时间和确认推送结果。平台接受私聊后提示超管回复“同意 编号”；部分或全部发送失败会显示错误码，申请不会丢失，超管仍可私聊 `/待确认列表` 后同意或拒绝。尚未同意的申请不建立正式比赛或提醒；批准时只创建未来节点。例如 10:15 开赛，若 09:46 才批准，就只创建 10:00 的15分钟前提醒，不补发已错过的09:45节点。官方主动私聊仍受平台权限与频控限制，错误码可用于排查，不能把创建了申请当作已送达。

在群内成功执行 `/加群` 或 `/加老师` 后，机器人除原群回执外还会私聊超管确认；若全部或部分私聊失败会在原群提示，授权记录不回滚。超管私聊执行管理命令时仍在当前私聊直接回复。私聊发送受机器人连接、好友关系与平台权限限制，数据已保存不代表通知已送达。

简单闲聊（如“你好”“谢谢”“还可爱呢”“哈哈哈”“收到”）默认从本地短句中选择回复，0 token，不读群资料、不记入未答问题。可设置 `ACM_QA_SOCIAL_CHAT_USE_LLM=1` 改用最多 60 输出 tokens 的轻量模型，3 秒超时后回到本地回复。混合队务问题仍走知识库，权限与限流照常生效。FAQ 直接回复老师录入的答案；比赛查问优先显示所问字段，没登记的字段会明确说明。老师/超管的模型问答使用精简提示词、紧凑且省略空字段的上下文，最多输出 240 tokens（同时受全局输出上限约束）。

进入问答前先在本地判断是否在查信息：明确问句、查找请求及“报名方式”“校赛时间”等短查询会继续检索；普通陈述不自动登记为问题，也不调用 FAQ 消歧或问答模型。非问句完整命中已录入 FAQ 词条时仍可直接回答。难以判断的表达会提示继续说，不猜测用户有问题；需要明确登记时发送 `/提问 问题内容`。关闭 `ACM_QA_SOCIAL_CHAT_ENABLED` 后，非提问消息可直接忽略，不会转为未答问题。

老师的自然语言发布仍可由 `ACM_NL_INTENT_ENABLED` 控制，分类前先检查问答权限、敏感内容与限流；明显问句和寒暄不调用发布分类模型。需要分类的比赛陈述最多输入 1200 字符、输出 32 tokens，3 秒超时后回到查询路径。

自然语言问答默认动态注入本群教务事实（`ACM_QA_CONTEXT_ENABLED=1`）：每次提问实时汇总未来 7 天课程、开放中的征集（标题、ID、截止时间、剩余名额、登记字段）与本群 FAQ，拼成一段纯文本事实块随 system prompt 送给模型，模型只按事实作答，时间、地点、名额、ID 原样引用，不猜不编。需要用户动手时只允许引导 `/课程列表`、`/校安排`、`/征集汇总`、`/报名 <征集ID>`、`/FAQ列表`、`/比赛状态`、`/提醒状态`、`/帮助` 这些真实命令。事实完全覆盖不到时模型只回内部标记 `[未收录]`，链路随即平滑转成未答问题工单并回问题编号，不再靠关键词硬匹配。上下文长度上限由 `ACM_QA_CONTEXT_MAX_CHARS`（默认 3000）控制，超长按行截断，三路数据全空时不注入（不额外花 token）。普通成员默认仍在 FAQ/已录入资料间作答、0 token；如需他们也能享受上下文作答，设置 `ACM_QA_MEMBER_CONTEXT_ANSWER=1`，此时模型判定未收录才转工单。

FAQ 优先在本群做本地检索：规范同义问法，区分时间、地点、报名流程等意图，对相近但不同答案保留歧义，不按记录顺序猜。普通成员一次提问只查询一次 FAQ 列表，默认不调用模型。建议把一条 FAQ 写成一个明确问题，时间、地点、报名方式分别维护；老师可继续用 `/回答 编号 = 答案` 沉淀常见问题。

本地匹配会排除不同比赛、届次、星期、否定条件以及报名/截止/开赛时间的错配。FAQ 只写泛泛的主题、未说明用户所问事项时，不直接当作确定答案；建议把“校赛报名”写成“校赛在哪里报名”等完整问题。明显冲突的候选也不会交给模型猜测。

如需模型识别口语意图，设置 `ACM_QA_FAQ_LLM_ENABLED=1` 并重启：仅在本地结果不确定时发送最多 5 条本群候选问题（不发送答案、报名资料、其他群内容），输出上限 24 tokens，3 秒超时。模型只能返回已有候选编号或“无匹配”，不能生成事实答案。相同群、问题及候选版本缓存 5 分钟，并发重复查询共用一次请求；资料修改立即使下次查询失效，模型返回后也复核是否仍有效。无可靠匹配继续收集为未答问题。超过长度上限的问题保留本地检索与人工处理，避免截掉关键条件后误选。

`/征集汇总 <id>` 对本群成员开放，只回复人数、取消人数和剩余名额。老师或超管发起查询时也不在群中展示成员标识、姓名、学号等报名明细。

明细由具有本机数据库访问权限的部署管理员导出并单独交付老师。导出命令只读取指定群的征集，只包含仍报名的成员，输出到新的本地 CSV 文件；不会发送到 QQ，也不会覆盖已有文件：

```powershell
New-Item -ItemType Directory -Force private-exports
python scripts/export_collection.py --group-id '群openid' --collection-id 1 --output private-exports/collection-1.csv
```

默认读取 `ACM_DB_PATH` 指定的数据库，也可传入 `--db '数据库路径'`。`private-exports/` 已加入 Git 忽略规则。

超管修正比赛可直接使用完整日期时间和带空格的文本，例如：

```text
/修正 1 official_reg_deadline=2026-12-01 23:59 name=ICPC 2026 区域赛
/修正 1 rules="先填写 name=姓名，再提交资料" site="https://example.com/contest?a=1,b=2"
```

多个字段用空白或中英文逗号分隔；值中包含由空白或逗号引出的 `字段=值` 片段（如 URL 中的 `,b=2`）时，用单引号、双引号或中文引号包裹。引号内可用反斜杠转义结束引号和反斜杠。`summary=""` 等空值可清空可选字段；同一字段及其别名不能重复指定。

`/报名 <征集id>` 重复发送会保留原登记资料；`/报名 <征集id> name="Alice Smith"` 仅更新指定字段，不删除其他资料。用 `字段=""` 明确清空某个字段；格式错误会返回提示，整次报名不写入。报名状态、截止和名额检查与写入使用同一事务。

## 正式启用前清空业务数据

`scripts/reset_business_data.py` 清空指定数据库中的全部比赛、课程、FAQ、未答问题、征集和报名、待审批、来源版本、提醒队列/回执及审计记录。保留 `.env`（含超管、凭据及参数）、现有群/老师权限、标识名称和群通知格式/权限暂停设置。只清数据库业务记录，不处理日志或导出的文件。

脚本只需 Python 3.10+ 标准库，不启动机器人、不加载或补写配置。默认只预览表名和数量；加 `--apply` 后先在数据库旁的 `backups/` 创建完整 SQLite 备份并核验，再在单个事务内清理。备份失败不删除，中途失败全部回滚。不会把写错的数据库路径创建成空库，遇到未知业务表会拒绝清理。历史自增编号保留，避免旧的“同意 编号”指向新申请。

在云端项目目录执行。下面以默认数据库 `contests.db` 为例；如果服务的 `ACM_DB_PATH` 指向其他文件，请将两条命令的 `--db` 都改为该文件的实际路径。实际清理前必须停止服务，完成后再启动：

```bash
cd /home/ubuntu/qq-bot
git pull --ff-only
systemctl stop acm-bot
python3 scripts/reset_business_data.py --db ./contests.db
```

核对预览中的数据库路径和数量后执行：

```bash
python3 scripts/reset_business_data.py --db ./contests.db --apply
systemctl start acm-bot
```

成功时会打印备份的完整路径。重启后旧业务和旧提醒均已清空，群权限和已验证的 Markdown 格式沿用；定时生成的业务会按现有配置重新产生。群内可发送 `/问题列表`（老师/超管）查看空列表，再验证普通闲聊不再生成问题编号。云端清理与真实收信仍需在实际部署环境验收；本地测试不代替云端执行。

## 安全与健壮性设计

- **权限默认全拒绝**：群、超管、老师白名单未配置时对应权限不开放；身份只取协议事件，不信正文声明。超管白名单控制全局管理与审批；老师白名单控制日常管理；`can_manage_group = 老师 ∪ 超管`，超管可执行老师管理功能，无需重复配置。普通成员可查询、报名和提问。
- **SSRF 防护**：仅支持无账号密码的 http/https；每次连接前解析并校验目标主机全部地址（拒绝回环 / 私网 / 链路本地 / 保留 / 组播 / 未指定，IPv4+IPv6）；socket 直连已校验 IP，规避 DNS 重绑定；手动逐跳跟随重定向并重新校验；可选域名白名单。
- **资源限制**：响应体按 Content-Length 提前拒绝 + 流式读取上限 + gzip 边解压边限流；正文、模型输入/输出、并发均有上限。
- **数据校验**：模型提取结果严格结构校验（名称必填、时间合法并归一化）；**校验失败不写库、不回复成功**；公共来源提取结果映射后再次经 `create_competition`/`update_competition` 严格 schema 校验，失败只记来源 error、不生成草稿。
- **时区统一**：业务时间统一北京时间 `Asia/Shanghai`（zoneinfo），UTC 主机同样按北京时区计算，格式 `YYYY-MM-DD HH:MM`。
- **提醒去重**：去重键含群号并持久化在 `reminder_deliveries`；SQLite 原子领取后进入 sending（120 秒租约），新旧提醒发送均有 60 秒超时和逐条异常处理，只有成功回执才标记 sent。每次领取消耗一次尝试，默认最多 3 次；进程中断后租约到期可恢复。发送前复核对象状态和时间；`/提醒状态` 按本群显示队列与终结状态统计。
- **公共抓取**：集中低频调度；ETag / Last-Modified / 正文哈希变化检测；**仅正文变化才调用模型**。已确认比赛保留原资料，变化写为待审更新，超管批准后合并；停用来源与过期抓取快照不能覆盖新资料。

## 已知问题

- **真实 QQ 验收范围**：11月7日已验证群主授权后，官方群 Markdown 主动测试消息送达且 `allow_proactive_msg=true`。未来比赛定时提醒与正式全流程仍待真实验收，离线回归不能代替到点收信。
- **主动通知待真实联调**：真实发送接口已接入，默认开启（`ACM_GROUP_ACTIVE_MESSAGES_ENABLED=0` 可关闭）；平台未授权、接收群拒绝、机器人离线或频控均可能导致发送失败，反馈以接口回执为准。
- **模型提取可能幻觉**：字段可能不准确，默认先由超管确认，发布后可 `/修正`；部署时关闭发布确认会跳过人工把关。
- **旧库记录归属为空**：旧版 `contests` 表迁移后旧记录不归属任何群、不参与提醒，需管理员人工按需迁移。
- **老师身份手工配置**：老师白名单基于 OneBot 的成员 QQ 号（`user_id`），需部署时手工收集 QQ 号填入 `ACM_TEACHER_WHITELIST`，暂不支持自动识别群管理员。

## 待平台授权 / 当前限制

- **启用群主动消息**：设置 `ACM_GROUP_ACTIVE_MESSAGES_ENABLED=1`，并确认当前协议已连接。OneBot 通过 NapCat 的 `send_group_msg` 发送；官方 QQ 通过群消息接口发送，还受机器人权限与目标群“允许主动发送”设置控制。仅返回有效消息 ID 才确认平台接受；权限、频控、超时或空回执均不标记为已发送。已有权限暂停的群需由超管主动测试成功后恢复。
- **关闭与失败反馈**：设置 `ACM_GROUP_ACTIVE_MESSAGES_ENABLED=0` 时，发布和修正仍保存资料并回复触发群，跨群通知明确显示未发送；定时提醒暂停，不消耗投递重试次数。老师可用 `/提醒状态` 查看启用状态。启用后每个目标群独立投递，一个群失败不阻止其他群，结果显示已确认发送的数量。
- **群通知与 @全体**：本项目使用文本或本群已验证的原生 Markdown 发送普通通知，未实现全员提醒。参见 [官方群消息接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html) 与 [消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)。
- **老师身份来源**：目前老师白名单以 OneBot 的成员 QQ 号（`user_id`）为准，需在部署环境将老师 QQ 号配置进 `ACM_TEACHER_WHITELIST`；如 QQ 侧能提供群管理员角色字段，可进一步自动识别管理员。
- **个人信息日志**：默认不记录群号、QQ 号和消息内容；初次部署采集白名单时可临时设置 `ACM_DEBUG_LOG_IDENTITY=1` 开启调试日志，采集完成后请关闭。
- **公共来源抓取**：`/抓取一次` 与周期抓取会真实调用抓取层（SSRF 防护生效）；无法访问目标站点时记录 error，可用 `/抓取状态` 查看。v2 自动抓取结果不自动通知群。
- **模型提取质量**：比赛信息由大模型提取生成，可能包含幻觉；超管确认前不会入库、不会通知各群。

## 旧库迁移

旧版 `contests` 表无 `group_id` 列。启动时自动迁移：补列并将旧记录归属置空（不删除任何数据）。旧记录默认不暴露给任何群、不参与提醒，需管理员人工按需迁移（参考 `database.list_contests()` 管理查询）。
