成都理工大学工程技术学院 ACM 集训队 QQ 群机器人：老师发布比赛链接 → 自动抓取、提取、存档；公共比赛资料统一管理，群订阅隔离；活动登记（报名/设备借用/出勤）自动统计；定时提醒与可选公共来源抓取（主动通知默认关闭）。

技术栈：Python 3.10+ / qq-botpy / SQLite / OpenAI 兼容大模型 API / APScheduler。

## 功能总览（四阶段）

| 阶段 | 功能 | 状态 |
|------|------|------|
| 一 | 发布存档、群内问答、定时提醒、按群隔离、旧库迁移 | 已实现 |
| 二 | 三层数据模型（公共比赛/学校安排/群内安排）、群订阅与跨群隔离、老师草稿审核、课程与 FAQ、未答问题收集 | 已实现 |
| 三 | 通用活动登记与统计（报名意向/设备借用/出勤）、个人幂等登记/取消/查询、管理员明细+普通成员汇总、持久化提醒去重与失败重试、主动提醒接入 | 发送接口已接入，默认关闭，见「待平台授权」 |
| 四 | 公共来源集中低频抓取、ETag/Last-Modified/正文哈希变化检测、实质变化才调一次模型 | 抓取可选；v2 自动抓取结果不自动通知群 |

### 数据模型（SQLite 演进）

- **公共比赛（competitions）**：跨群共享对象，老师（或来源抓取）创建草稿 → 审核通过（confirmed）→ 群通过 `group_competitions` 关联表订阅；所有公共对象不内嵌 `group_id`，通过关联表授予群访问，数据库层按群过滤，不依赖模型提示词。
- **学校安排（org_events）**：学校统一安排，`shareable=1` 的公开项所有群可看。
- **群内安排（training_sessions / faqs / unanswered_questions / activities）**：全部带 `group_id`，严格按群隔离。
- **活动登记（activity_responses）**：同一活动+成员幂等登记（仅一条 registered），取消置 cancelled 保留记录；容量校验、截止时间校验、字段白名单校验。
- **提醒投递（reminder_deliveries）**：去重键含群号（`group_id|obj_type|obj_id|remind_type|target`，自动迁移旧冒号键），发送成功才标记 sent，失败留 pending 有界重试，耗尽后 failed；关闭/改期计划 cancelled，超过目标时间 expired。
- **来源抓取（competition_sources）**：记录 ETag/Last-Modified/正文哈希/最近抓取时间/状态/错误，支撑低频抓取与变化检测。

发布比赛时，正式比赛、来源 URL 和已抓取正文的哈希在同一事务保存。开启 `ACM_AUTO_FETCH_ENABLED=1` 后，新发布链接按 `ACM_FETCH_MIN_INTERVAL_MINUTES` 进入后台监控；正文未变化不再调用模型，有变化则保存待审更新。`/抓取状态` 可查看来源登记与最近检查结果。

## 消息指令

| 场景 | 示例 | 权限 | 行为 |
|------|------|------|------|
| 发布比赛 | `@机器人 发布 https://example.com/contest` | 发布白名单 | 抓取 → 提取 → 校验 → 按群存档 → 回复确认 |
| 订阅公共比赛 | `/订阅 蓝桥杯` | 群成员 | 订阅已审核通过的公共比赛到本群 |
| 取消订阅 | `/取消订阅 蓝桥杯` | 群成员 | 取消本群订阅 |
| 比赛列表/详情 | `/比赛列表`、`/比赛详情 3` | 群成员 | 查看本群订阅（数据库层按群过滤） |
| 审核草稿 | `/审核列表`、`/审核通过 3`、`/审核拒绝 3 原因` | 老师白名单 | 草稿确认/拒绝，记录版本与拒绝说明 |
| 学校安排 | `/校安排` | 群成员 | 查看公开的学校统一安排 |
| 课程 | `/课程列表`、`/课程添加 …`、`/课程取消 2` | 列表群成员，增删老师 | 本群课程安排 |
| FAQ | `/FAQ列表 [词]`、`/FAQ添加 问 = 答`、`/FAQ删除 1` | 增删老师 | 本群 FAQ |
| 提问 | `/提问 问题` | 群成员 | 记录未答问题；`/问题列表` 老师查看 |
| 活动 | `/活动创建 集训报名 2026-11-10 23:59 50 姓名,学号` | 老师 | 创建活动（报名意向/设备借用/出勤） |
| 登记/取消/查询 | `/登记 1 姓名=张三`、`/取消登记 1`、`/我的登记 1` | 群成员 | 幂等登记/取消/查询个人记录 |
| 汇总/明细/关闭 | `/活动汇总 1`、`/活动明细 1`、`/活动关闭 1` | 汇总群成员，明细/关闭老师 | 普通成员只见汇总（人数/名额），管理员见明细 |
| 提醒状态 | `/提醒状态` | 老师 | 查看投递队列与重试情况 |
| 抓取状态 | `/抓取状态`、`/抓取一次` | 老师 | 查看公共来源抓取状态；立即触发一次抓取 |
| 帮助 | `/帮助` | 群成员 | 完整命令帮助 |

完整帮助运行 `/帮助` 获取；所有命令为斜杠开头（`/`），避免与普通提问混淆。

`/征集汇总 <id>` 对本群成员开放，只回复人数、取消人数和剩余名额。老师或超管发起查询时也不在群中展示成员标识、姓名、学号等报名明细。

明细由具有本机数据库访问权限的部署管理员导出并单独交付老师。导出命令只读取指定群的征集，只包含仍报名的成员，输出到新的本地 CSV 文件；不会发送到 QQ，也不会覆盖已有文件：

```powershell
New-Item -ItemType Directory -Force private-exports
python scripts/export_collection.py --group-id '群openid' --collection-id 1 --output private-exports/collection-1.csv
```

默认读取 `ACM_DB_PATH` 指定的数据库，也可传入 `--db '数据库路径'`。`private-exports/` 已加入 Git 忽略规则。

超管修正比赛可直接使用完整日期时间和带空格的文本，例如：

```text
/修正 1 official_reg_deadline=2026-12-01 23:59 name=ICPC 2026 区域赛
/修正 1 rules="先填写 name=姓名，再提交资料" site="https://example.com/contest?a=1,b=2"
```

多个字段用空白或中英文逗号分隔；值中包含由空白或逗号引出的 `字段=值` 片段（如 URL 中的 `,b=2`）时，用单引号、双引号或中文引号包裹。引号内可用反斜杠转义结束引号和反斜杠。`summary=""` 等空值可清空可选字段；同一字段及其别名不能重复指定。

`/报名 <征集id>` 重复发送会保留原登记资料；`/报名 <征集id> name="Alice Smith"` 仅更新指定字段，不删除其他资料。用 `字段=""` 明确清空某个字段；格式错误会返回提示，整次报名不写入。报名状态、截止和名额检查与写入使用同一事务。

## 配置（环境变量）

| 变量 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `ACM_APPID` | 是 | - | QQ 机器人 AppID |
| `ACM_APP_SECRET` | 是 | - | QQ 机器人 AppSecret（日志严禁打印） |
| `ACM_GROUP_ACTIVE_MESSAGES_ENABLED` | 否 | `0` | 仅设为 `1` 时启用群主动通知与定时提醒投递；需确认平台和接收群允许主动消息 |
| `ACM_LLM_API_KEY` | 是 | - | 大模型 API Key（OpenAI 兼容） |
| `ACM_LLM_BASE_URL` | 否 | `https://api.deepseek.com/v1` | 大模型接口地址 |
| `ACM_LLM_MODEL` | 否 | `deepseek-chat` | 模型名 |
| `ACM_ALLOWED_GROUPS` | 否 | 空 | 允许服务的群 openid 列表（逗号分隔）。**未配置 = 不服务任何群** |
| `ACM_PUBLISHER_WHITELIST` | 否 | 空 | 有权发布比赛的成员 openid 白名单。**未配置 = 不允许任何人发布** |
| `ACM_TEACHER_WHITELIST` | 否 | 空 | 老师 openid 白名单（审核草稿/课程/FAQ/活动管理等）。**未配置 = 无任何老师权限** |
| `ACM_PUBLISH_CMD` | 否 | `发布` | 发布命令前缀 |
| `ACM_FETCH_ALLOWED_DOMAINS` | 否 | 空 | 可抓取的域名白名单（逗号分隔，小写）；重定向目标同样校验。**强烈建议配置** |
| `ACM_FETCH_MAX_BYTES` | 否 | `1000000` | 解压后响应体上限（字节） |
| `ACM_FETCH_MAX_REDIRECTS` | 否 | `3` | 重定向跳数上限 |
| `ACM_FETCH_TIMEOUT` | 否 | `10` | 连接 / 读取超时（秒） |
| `ACM_FETCH_CONCURRENCY` | 否 | `2` | 同时抓取上限 |
| `ACM_FETCH_TEXT_LIMIT` | 否 | `3000` | 送入模型的正文长度上限（字符） |
| `ACM_FETCH_MIN_INTERVAL_MINUTES` | 否 | `60` | 公共来源最小抓取间隔（分钟），低频抓取控制 |
| `ACM_LLM_MAX_INPUT_CHARS` | 否 | `6000` | 单次模型请求输入上限 |
| `ACM_LLM_MAX_OUTPUT_TOKENS` | 否 | `2000` | 单次模型请求输出上限 |
| `ACM_LLM_CONCURRENCY` | 否 | `2` | 模型并发请求上限 |
| `ACM_REMIND_CHECK_INTERVAL_MINUTES` | 否 | `30` | 提醒检查周期（分钟） |
| `ACM_REMIND_BEFORE_HOURS` | 否 | `24` | 提前多少小时提醒 |
| `ACM_DB_PATH` | 否 | `./contests.db` | SQLite 数据库路径 |

启动前 `check_config()` 会校验必填项，缺失时抛出缺失项名（不打印密钥值）。**密钥一律不进源码 / 日志 / 测试**。

## 安全与健壮性设计

- **权限默认全拒绝**：群白名单、发布者白名单、老师白名单未配置时均不开放；身份一律取自 SDK 事件字段（`group_openid` / `member_openid`），不信消息正文中的身份声明；老师身份判断走 `ACM_TEACHER_WHITELIST`，未配置则所有 `/审核通过`、`/活动创建` 等命令拒绝执行。
- **SSRF 防护**：仅支持无账号密码的 http/https；每次连接前解析并校验目标主机全部地址（拒绝回环 / 私网 / 链路本地 / 保留 / 组播 / 未指定，IPv4+IPv6）；socket 直连已校验 IP，规避 DNS 重绑定；手动逐跳跟随重定向并重新校验；可选域名白名单。
- **资源限制**：响应体按 Content-Length 提前拒绝 + 流式读取上限 + gzip 边解压边限流；正文、模型输入/输出、并发均有上限。
- **数据校验**：模型提取结果严格结构校验（名称必填、时间合法并归一化）；**校验失败不写库、不回复成功**；公共来源提取结果映射后再次经 `create_competition`/`update_competition` 严格 schema 校验，失败只记来源 error、不生成草稿。
- **时区统一**：业务时间统一北京时间 `Asia/Shanghai`（zoneinfo），UTC 主机同样按北京时区计算，格式 `YYYY-MM-DD HH:MM`。
- **提醒去重**：去重键含群号并持久化在 `reminder_deliveries`；SQLite 原子领取后进入 sending（120 秒租约），新旧提醒发送均有 60 秒超时和逐条异常处理，只有成功回执才标记 sent。每次领取消耗一次尝试，默认最多 3 次；进程中断后租约到期可恢复。发送前复核对象状态和时间；`/提醒状态` 按本群显示队列与终结状态统计。
- **公共抓取**：集中低频调度（`FETCH_MIN_INTERVAL_MINUTES`）；ETag / Last-Modified / 正文哈希三层变化检测，以正文哈希为强信号；**仅实质变化才调用一次模型**生成审核草稿；已确认比赛被实质变化打回草稿需重新审核；订阅群与来源异常均返回通知目标，由发送回调统一处理。

## 已知问题

- **未完成真实 QQ 联调**：所有行为验证均基于离线测试；真实群的消息格式、@ 解析、回复链路、审核与登记交互尚未实测，可能暴露平台差异。
- **主动通知待真实联调**：真实发送接口已接入，默认关闭；平台未授权、接收群拒绝、机器人离线或频控均可能导致发送失败，反馈以接口回执为准。
- **模型提取可能幻觉**：草稿由大模型从抓取正文提取生成，字段可能不准确；老师审核通过前成员不可见，但提取错误仍可能误导审核。
- **旧库记录归属为空**：旧版 `contests` 表迁移后旧记录不归属任何群、不参与提醒，需管理员人工按需迁移。
- **老师身份手工配置**：老师白名单基于 SDK `member_openid`，需部署时手工收集 openid 填入 `ACM_TEACHER_WHITELIST`，暂不支持自动识别群管理员。

## 待平台授权 / 当前限制

- **启用群主动消息**：先确认机器人已连接 QQ WebSocket、平台允许发送且目标群允许接收主动消息，再设置 `ACM_GROUP_ACTIVE_MESSAGES_ENABLED=1` 并启动机器人。`main._send_group` 调用 `post_group_message`，不携带其他群消息的 `msg_id` / `event_id`；仅返回有效消息 `id` 才视为发送成功。权限、频控、超时或空回执均不标记为已发送。
- **关闭与失败反馈**：默认关闭时，发布和修正仍保存资料并回复触发群，跨群通知明确显示未发送；定时提醒暂停，不消耗投递重试次数。老师可用 `/提醒状态` 查看启用状态。启用后每个目标群独立投递，一个群失败不阻止其他群，结果显示已确认发送的数量。
- **群通知与 @全体**：本项目使用普通群文本消息。公开接口没有 `@全体` 参数，因此不声称已触发全员提醒。参见 [官方群消息接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html) 与 [消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)。
- **老师身份来源**：目前老师白名单以 SDK 的 `member_openid` 为准，需在部署环境将老师 openid 配置进 `ACM_TEACHER_WHITELIST`；如 QQ 侧能提供群管理员角色字段，可进一步自动识别管理员。
- **公共来源抓取**：`/抓取一次` 与周期抓取会真实调用抓取层（SSRF 防护生效）；无法访问目标站点时记录 error，可用 `/抓取状态` 查看。v2 自动抓取结果不自动通知群。
- **模型提取质量**：草稿由大模型提取生成，可能包含幻觉；老师审核通过前不会对成员可见（订阅命令只允许订阅 confirmed 资料）。

## 旧库迁移

旧版 `contests` 表无 `group_id` 列。启动时自动迁移：补列并将旧记录归属置空（不删除任何数据）。旧记录默认不暴露给任何群、不参与提醒，需管理员人工按需迁移（参考 `database.list_contests()` 管理查询）。
